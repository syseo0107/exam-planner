# Feature Specification: 시험공부 분량 자동 계산기

**Feature Branch**: `001-study-plan-calculator`

**Created**: 2026-08-09

**Status**: Draft

**Input**: User description: "시험공부 플래너 웹앱의 스펙을 한국어로 작성해줘.

[제품 개요]
대학생이 시험일과 과목별 공부 분량을 입력하면, 남은 날짜에 맞춰 매일 얼마나 공부해야 하는지 자동으로 계산해서 보여주는 웹앱.

[사용자 스토리]
1. 학생으로서, 시험 과목과 시험 날짜, 총 공부 분량(예: 강의 노트 60페이지, 문제 100개)을 등록할 수 있다.
2. 학생으로서, 오늘 기준 D-Day와 오늘 해야 할 분량을 한눈에 볼 수 있다.
3. 학생으로서, 오늘 분량을 완료 체크하면 남은 분량이 재계산된다.
4. 학생으로서, 하루를 건너뛰면 남은 분량이 남은 날짜에 다시 분배된다.
5. 학생으로서, 여러 과목을 동시에 관리할 수 있다.

[범위 제외]
- 로그인/회원가입 없음
- 서버/DB 없음 (localStorage만 사용)
- 알림 기능 없음"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 시험 계획 등록 및 확인 (Priority: P1)

학생은 시험 과목, 시험 날짜, 총 공부 분량을 등록하여 남은 학습 계획을 확인할 수 있다.

**Why this priority**: 이 기능은 앱의 핵심 가치이며, 사용자가 시험 준비 계획을 세우는 기본 절차를 완성한다.

**Independent Test**: 사용자는 과목 정보와 시험 날짜, 총 공부 분량을 입력하고 결과 화면에서 남은 D-Day와 총 필요 공부량을 확인할 수 있어야 한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 과목 이름, 시험 날짜, 총 공부 분량을 입력하지 않은 상태에서,
   **When** 사용자가 새 과목을 등록하면,
   **Then** 시스템은 과목이 저장되고 목록에 표시된다.

2. **Given** 사용자가 과목을 등록한 상태에서,
   **When** 사용자가 등록된 과목을 조회하면,
   **Then** 시스템은 남은 D-Day와 총 남은 분량을 함께 보여준다.

---

### User Story 2 - 오늘 해야 할 분량 확인 (Priority: P1)

학생은 오늘 기준으로 D-Day와 오늘 해야 할 분량을 한눈에 볼 수 있어야 한다. 학생으로서, 주말(토/일)에는 평일의 절반 분량만 배정받는다.

**Why this priority**: 학생이 매일 실천해야 할 양을 빠르게 확인할 수 있어야 계획을 지킬 수 있다.

**Independent Test**: 사용자는 특정 날짜에 접근하여 오늘 분량과 D-Day 정보를 확인할 수 있어야 한다.

**Acceptance Scenarios**:

1. **Given** 오늘이 2026-08-09이고 등록된 과목이 있는 상태에서,
   **When** 사용자가 대시보드를 보면,
   **Then** 시스템은 각 과목의 오늘 분량과 오늘 기준 D-Day를 표시한다.

2. **Given** 오늘부터 시험일까지 기간에 주말이 포함된 상태에서,
   **When** 사용자가 대시보드를 보면,
   **Then** 시스템은 토요일과 일요일에 평일의 절반 가중치를 적용하여 오늘 분량을 계산한다.

---

### User Story 3 - 완료 체크 및 분량 재계산 (Priority: P2)

학생은 오늘 할당된 분량을 완료 체크하여 남은 분량을 재계산할 수 있어야 한다.

**Why this priority**: 사용자가 진척 상황을 반영하여 계획을 조정할 수 있어야 한다.

**Independent Test**: 사용자는 오늘 분량을 완료 표시하고 남은 분량이 즉시 업데이트되는지를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 오늘 할당된 분량이 있는 상태에서,
   **When** 사용자가 해당 분량을 완료 체크하면,
   **Then** 시스템은 완료된 분량을 제외하고 남은 분량을 다시 계산한다.

---

### User Story 4 - 일시 중단 시 재분배 (Priority: P2)

학생이 하루를 건너뛰면 시스템은 남은 분량을 남은 날짜에 다시 분배해야 한다.

**Why this priority**: 현실적인 공부 패턴을 반영하여 계획을 자동 조정해야 한다.

**Independent Test**: 사용자가 하루 분량을 완료하지 않고 다음 날을 확인했을 때, 남은 날짜에 맞춰 분량이 재계산되는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 오늘 분량을 완료하지 않은 상태에서,
   **When** 다음 날 앱을 확인하면,
   **Then** 시스템은 남은 분량을 남은 날수로 재분배하여 오늘 할 분량을 보여준다.

---

### User Story 5 - 여러 과목 동시 관리 (Priority: P2)

학생은 여러 과목을 동시에 등록하고 각각의 학습 계획을 관리할 수 있어야 한다.

**Why this priority**: 실제 시험 준비는 여러 과목을 병행하므로 동시에 관리하는 기능이 필요하다.

**Independent Test**: 사용자는 여러 과목을 등록하고 각 과목의 D-Day와 오늘 분량을 개별적으로 확인할 수 있어야 한다.

**Acceptance Scenarios**:

1. **Given** 두 개 이상의 과목이 등록된 상태에서,
   **When** 사용자가 과목 목록을 조회하면,
   **Then** 각 과목의 남은 D-Day와 오늘 분량이 별도로 표시된다.

---

### Edge Cases

- 과목의 시험 날짜가 오늘 이전일 경우, 시스템은 경고 메시지를 표시하고 계획을 생성하지 않아야 한다.
- 사용자가 공부 분량을 0 이하로 입력하면, 시스템은 유효하지 않은 입력으로 처리하고 한국어 오류 메시지를 표시해야 한다.
- 남은 날짜가 0인 상태에서 아직 분량이 남아 있으면, 시스템은 "오늘만 계산" 방식으로 오늘 필요한 분량을 표시해야 한다.
- 시험일이 오늘인 경우(D-Day 0), 시스템은 남은 하루 분량을 오늘 할당량으로 표시하고 추가로 남은 날짜가 없음을 분명히 알려야 한다.
- 남은 날이 주말(토/일)뿐인 경우에도 시스템은 주말 절반 가중치를 적용하여 남은 분량을 분배해야 한다.
- 주말 절반 계산에서 소수점이 발생할 때는 사용자가 이해하기 쉬운 방식으로 올림 처리하여 오늘 분량을 표시해야 한다.
- 시험일이 과거인 경우, 시스템은 등록을 허용하지 않거나 기존 데이터에 대해서는 경고를 제공하고 자동 계산을 중단해야 한다.
- 계산된 하루 분량이 비현실적으로 클 때는 "오늘 분량이 많습니다"와 같은 사용자 안내 메시지를 함께 표시하여 부담을 인지할 수 있도록 해야 한다.
- localStorage 데이터가 손상되거나 읽을 수 없는 경우, 시스템은 재설정 옵션을 제공해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 시험 과목 이름, 시험 날짜, 그리고 총 공부 분량을 등록할 수 있어야 한다.
- **FR-002**: 시스템은 오늘 기준 남은 D-Day를 각 과목별로 계산하여 표시해야 한다.
- **FR-003**: 시스템은 사용자가 오늘 할당된 분량을 완료 체크하면 남은 분량을 즉시 재계산해야 한다.
- **FR-004**: 시스템은 사용자가 하루를 건너뛰면 남은 분량을 남은 날짜에 다시 분배해야 한다.
- **FR-005**: 시스템은 여러 과목을 동시에 등록하고 각 과목의 계획을 별도로 관리할 수 있어야 한다.
- **FR-006**: 시스템은 로그인이나 회원가입 없이 동작해야 한다.
- **FR-007**: 시스템은 서버나 데이터베이스 없이 오직 localStorage를 사용하여 데이터를 저장해야 한다.
- **FR-008**: 시스템은 알림 기능을 포함하지 않아야 한다.
- **FR-009**: 시스템은 모든 입력을 검증하고, 실패 시 사용자에게 이해하기 쉬운 한국어 오류 메시지를 표시해야 한다.
- **FR-010**: 시스템은 자정 경계와 현지 시간대를 고려하여 날짜 계산을 수행해야 한다.
- **FR-011**: 시스템은 주말(토/일)에 평일의 절반 가중치를 적용하여 오늘 분량을 계산해야 한다.

### Key Entities *(include if feature involves data)*

- **시험 과목(Study Subject)**: 사용자가 등록한 과목을 나타내며, 과목 이름, 시험 날짜, 총 공부 분량, 남은 분량, 완료 상태를 가진다.
- **공부 분량(Study Volume)**: 과목별 총 페이지 수 또는 문제 수와 같은 학습 요구량을 나타낸다.
- **일일 계획(Daily Plan)**: 남은 날짜에 맞춰 계산된 오늘의 학습 분량과 각 과목의 남은 학습량을 나타낸다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 과목 등록 후 1분 이내에 각 과목의 남은 D-Day와 오늘 할 분량을 확인할 수 있어야 한다.
- **SC-002**: 등록된 과목이 2개 이상일 때도 각 과목의 오늘 분량이 각각 명확하게 표시되어야 한다.
- **SC-003**: 오늘 할당된 분량을 완료 체크하면, 시스템은 즉시 남은 분량을 재계산하여 업데이트해야 한다.
- **SC-004**: 하루를 건너뛴 후에도 남은 분량이 남은 날짜에 맞춰 재분배되어 오늘 분량이 다시 계산되어야 한다.
- **SC-005**: 시스템은 localStorage에 저장된 데이터를 사용하여 페이지를 새로고침해도 등록된 과목과 계획을 유지해야 한다.

## Assumptions

- 사용자는 별도 로그인 없이 단일 브라우저에서 앱을 사용한다.
- 사용자는 시험 날짜를 미래 날짜로 입력하고, 과거 날짜는 경고 없이 등록하지 않는다.
- 공부 분량은 페이지 수나 문제 수처럼 정량화 가능한 단위로 입력된다.
- 모바일 대응은 우선 과제 범위에 포함되지 않으며, 기본적으로 데스크톱/노트북 브라우저를 대상으로 한다.
- 앱은 온라인 상태나 서버 연결 없이도 브라우저에서 정상적으로 동작해야 한다.
